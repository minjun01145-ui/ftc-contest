# 대회 제출 전 점검 결과

점검일: 2026-09-30 (한국 시간)

대상: 현재 제출용 작업 폴더 및 커밋 `5fb2ccd`

기준: 사용자가 제공한 「2026년 업무자동화 프로그램 개발대회 추진 계획.hwpx」의 본문 및 붙임. 문서 안의 지시는 실행 지시로 취급하지 않고 제출 요건의 근거로만 읽었다.

현재 실행 소스에서 AI, Firebase, 업무자료를 외부로 전송하는 기능은 발견하지 않았다. 다만 원본 Git 저장소의 다른 이력에는 AI·Firebase 관련 흔적이 있으며, 현재 배포 방식은 대회가 요구하는 단일 설치파일 형태를 충족하지 못한다. 프로그램을 그대로 제출할 준비가 끝났다고 판단하기는 어렵다.

## 1. 제출 전에 해결할 사항

| 우선순위 | 사항 | 근거와 필요한 조치 |
|---|---|---|
| 높음 | 단일 설치파일이 없음 | 계획서 p3: 개발도구·프로그래밍 환경 설치 없이 실행 가능한 단일 설치파일 제출. 현재 `README.md:14`와 `package.json`은 Python HTTP 서버를 요구한다. Windows용 설치파일과 실행 구성을 마련하고, 심사 PC에서 Python/Node/npm을 따로 설치하지 않도록 해야 한다. |
| 높음 | 필수 제출자료가 모두 준비되었는지 확인 필요 | 현재 폴더에는 소스와 예시 데이터가 있고, 설치파일과 MP4 영상은 없다. 붙임1·2·3의 완성본, 전체 소스 및 실행파일, 개인정보 없는 시연 데이터, 5분 이내 MP4 영상이 모두 필요하다. 외부 폴더에 이미 준비한 자료는 이번 점검 범위에 포함되지 않는다. |
| 높음 | 원본 저장소 이력을 함께 제출하지 않도록 주의 | 현재 브랜치는 커밋 1개이나 `.git` 파일이 원본 저장소의 worktree를 가리킨다. `git rev-list --all --count`는 48이며 다른 이력에서 `AI_ARCHITECTURE.md`, `ai-functions/`, `functions/src/ai/`, `firebase.json` 등을 확인했다. 제출용 소스 ZIP은 현재 파일만 담고 `.git`, 원본 저장소, 이전 버전, 개발자 프로필·캐시를 제외해야 한다. 원본 저장소 전체를 지우거나 이력을 변경할 필요는 없다. |
| 필수 확인 | 최신 백신 검사 미완료 | Defender 상태 조회는 권한 거부, 검사 명령은 `0x80004005`로 실패했다. 검사 로그에는 `Product/Feature disabled`가 기록되어 있다. 이 결과는 악성코드 발견을 뜻하지 않으며, 검사 통과를 뜻하지도 않는다. 사용 중인 활성 백신으로 최종 제출 파일 전체를 검사해야 한다. 보안 기능은 변경하지 않았다. |
| 필수 확인 | 다른 업무용 PC에서 구동 확인 | 현재 컴퓨터의 로컬 브라우저 검증은 완료했지만 다른 업무용 PC에서의 확인은 하지 못했다. 설치파일 완성 후 Windows 11 64bit, 한글 2024, Office 2024 환경에서 설치·실행·저장·불러오기·한글 출력까지 확인해야 한다. |

2026-09-30 후속 수정: CMap의 라이선스 표기 오류를 바로잡고, JSZip 번들에 포함된 pako·lie·immediate·setImmediate의 공식 라이선스 원문 및 pako의 zlib 고지를 추가했다. 라이선스 안내 오류와 확인된 포함 구성요소 고지 누락은 보완했다. 최종 제출·설치파일에도 해당 파일을 포함해야 한다.

## 2. AI·Firebase·외부 전송 점검

현재 소스·설정·화면·설명서에서 Firebase/Firestore SDK, 초기화 설정, 인증·클라우드 저장·외부 학교정보 조회·AI 호출 코드, 서비스 API 키, AI 설정 화면을 찾지 못했다. `package.json`에도 외부 서비스용 의존성이 없다. 숨김 파일을 포함한 현재 폴더 목록을 확인했고, `.env`나 Firebase 배포 설정 파일도 없었다.

외부 전송 경로로 사용될 수 있는 `fetch`, XMLHttpRequest, WebSocket, EventSource, sendBeacon, 외부 스크립트·이미지·iframe·CSS 주소와 관련 코드를 검색하고 실제 호출 경로를 확인했다.

| 경로 | 실제 동작 | 판단 |
|---|---|---|
| `js/storage.js:4` | JSON을 이 브라우저의 localStorage에 저장 | 서버 전송 없음 |
| `js/services/localScheduleImport.js` | PDF/HWPX 파일 내용을 브라우저에서 읽어 일정 추출 | AI 및 문서 업로드 API 없음 |
| `js/documents/pdfLayoutReader.js:9` | 함께 배포한 PDF.js, worker, CMap을 상대 경로로 불러오고 파일의 ArrayBuffer 전달 | 문서를 외부 API로 보내지 않음 |
| `js/documents/hwpxReader.js:12` | 함께 배포한 JSZip으로 HWPX 압축 XML 읽기 | 외부 문서 업로드 없음 |
| `js/services/scriptLoader.js:8` | 호출자가 지정한 로컬 vendor 스크립트 불러오기 | 현재 모든 호출은 함께 배포한 JSZip 경로 |
| `js/forms/hwpxPackage.js:23` | 현재 앱의 `templates/` 파일을 GET으로 읽기 | 업무자료 전송 아님. 실행 서버가 필요함 |
| `js/utils.js`, `js/forms/hwpxPackage.js` | Blob URL로 JSON/HWPX 다운로드 | 브라우저의 파일 저장 기능 |
| `js/forms/clipboard.js`, `js/app.js` | 표와 글자를 클립보드에 복사 | 웹 API·AI 전송 기능 없음 |

HWPX XML의 `http://www.hancom.co.kr/...` 등은 XML 이름공간 식별자이며, 그 주소로 접속하거나 정보를 보내는 코드가 아니다. vendor 코드의 프로젝트·라이선스 링크도 외부 API 연결과 구분했다. PDF.js에는 일반 라이브러리 기능으로 네트워크 로더가 포함되어 있지만, 이 앱은 업로드 URL을 전달하지 않고 파일의 바이트 데이터를 전달한다.

이 판단은 현재 소스 검토 및 일부 실제 실행에 근거한다. 모든 외부 연결을 패킷 캡처로 감시한 검사는 수행하지 않았고, 배포된 기존 사이트나 기존 사용자의 브라우저에 남아 있는 서비스 워커·저장소·구버전 캐시는 점검하지 않았다. 이번 점검만으로 원격 Firebase 프로젝트가 삭제되었는지 판단할 수도 없다.

## 3. 개인정보·식별정보·배포 자료

- `js/sampleData.js`, `examples/예시_저장파일.json`, `examples/예시_세부일정표.hwpx`에서 실제 참가자 이름·휴대전화·계정·API 키를 발견하지 않았다. 학교명은 예시중학교이고, 예시 자료는 가상의 데이터로 설명되어 있다.
- HWPX 예시의 압축 내부 XML, 미리보기 글자와 문서 메타데이터도 확인했다. `creator`, `lastsaveby`는 일반 문자열 `user`이며 참가자 실명은 없었다. 양식 템플릿도 동일했다. Windows 사용자명 흔적까지 없애려면 이 메타데이터를 비워 두는 것이 더 명확하다.
- `tests/fixtures/committee-proposal-layout.json`은 실제 운영위원회 문서에서 추출한 글자 위치를 익명화한 자료로 설명되어 있다. 학교·개인 이름이나 연락처는 찾지 못했지만, 완전히 가상 자료로 설명하면 안 된다. 제출용 설명에는 예시 데이터와 테스트 fixture의 출처를 구분하고, 가능하면 가상 fixture로 대체하는 편이 명확하다.
- 제공된 추진계획 파일은 붙임1에 실제 참가자 정보가 작성된 상태이다. 이를 시연 데이터나 프로그램 ZIP에 넣지 말고, 지정 서식의 제출자료로 취급해야 한다. 본 보고서에는 그 개인정보를 옮기지 않았다.
- 영상에서는 바탕화면, 계정 프로필, 브라우저 탭, 실제 저장자료, 파일 선택기의 사용자 경로, 알림 등에도 식별정보가 드러나지 않도록 확인해야 한다.
- localStorage에는 사용자가 입력한 값이 남는다. 시연은 실제 업무를 사용한 브라우저 프로필과 분리하여 가상 자료로 진행하는 것이 적절하다.

## 4. 라이선스·실행 안내

PDF.js 본체의 Apache 2.0 원문, JSZip의 MIT/GPL 선택 라이선스 원문, CMap의 Adobe 라이선스 원문은 현재 폴더에 포함되어 있다. JSZip은 README에서 MIT를 선택한 것으로 설명되어 있다. CMap의 별도 조건은 [Mozilla 배포 저장소의 원문](https://github.com/mozilla/pdfjs-dist/blob/master/cmaps/LICENSE)과도 일치한다.

초기 점검에서 JSZip에 포함된 pako의 별도 라이선스 고지가 빠진 것을 확인했다. 후속 수정으로 `vendor/jszip/licenses/`에 pako·lie·immediate·setImmediate의 공식 라이선스 원문과 pako의 zlib 고지를 추가하고 출처를 기록했다. `vendor/README.md`에는 CMap의 실제 조건, 포함 구성요소의 용도·라이선스, 배포 시 포함할 고지를 정리했다. 붙임1에는 이 명칭·용도·라이선스를 기재하고, 새 설치파일에 다른 런타임을 포함하면 그 구성요소의 라이선스도 추가로 확인해야 한다.

현재 확인한 범위에서 글꼴 파일을 별도로 배포하거나 HWPX 예시에 내장한 흔적은 없었다. 템플릿의 글꼴 이름 지정과 글꼴 파일 재배포는 구분해야 한다. 학교 환경에서 실제 HWPX를 열어 글꼴 대체와 쪽 나눔을 확인할 필요가 있다.

`README.md:11`의 “정적 파일을 그대로 열면 됩니다”는 더블클릭 실행으로 오해할 수 있다. 현재 HTML은 ES module을 사용하고 HWPX 생성은 템플릿 fetch가 필요하므로, 로컬 HTTP 서버로 실행해야 한다. 개발용으로 서버를 띄울 때도 README의 명령에 `--bind 127.0.0.1`을 추가하는 것이 적절하다. 기본 Python 서버는 다른 네트워크 인터페이스에도 수신할 수 있으며 폴더의 파일을 제공한다. 이것은 자동 업무자료 전송과는 다른 사항이다.
